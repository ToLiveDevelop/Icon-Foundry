# Icon Foundry

**Ваши иконки. Ваша тема.**

Android-приложение, которое превращает установленные иконпаки в темы `.hnt`
для штатного лаунчера HONOR MagicOS 10+. Android 15+, без root, рекламы,
сетевого доступа и разрешения на всю память.

[Сайт](https://tolivedevelop.github.io/Icon-Foundry/) ·
[Скачать APK](https://github.com/ToLiveDevelop/Icon-Foundry/releases/latest) ·
[Сообщить о проблеме](https://github.com/ToLiveDevelop/Icon-Foundry/issues)

## Возможности

- Обнаружение установленных иконпаков с `appfilter.xml`.
- До 10 паков-основ с приоритетом, который задаётся перетаскиванием:
  каждое приложение получает иконку из самого верхнего пака, где она есть.
- Ручная замена иконок, в том числе из других установленных паков. При нескольких
  паках-основах слева есть вкладки-иконки паков, а поиск идёт сразу по всем.
- Иконки из файлов с предпросмотром перед назначением. Копии изображений
  сохраняются внутри шаблона, исходные файлы после импорта не нужны.
- Экспорт только установленных приложений или всех сопоставлений пака,
  включая будущие установки.
- Маски для системных иконок: круг, скруглённый квадрат, сквиркл, квадрат с лёгким скруглением,
  капля, сердце, звезда, шестиугольник и скруглённый пятиугольник.
  Выбор в отдельном окне с шестью системными иконками на фоне обоев шаблона
  или градиента для предпросмотра. Размер — по типичному размеру иконок пака.
- Накладка поверх иконки из прозрачного PNG: только для системных иконок
  без замены либо для всех иконок. Есть предпросмотр; файл хранится в шаблоне.
- Обложка с обрезкой 9:16 или автообложка из 12 разных иконок:
  популярные приложения и алфавитное заполнение недостающих мест.
- Необязательные пользовательские обои для рабочего стола и блокировки.
- Шаблоны с параметрами, обложкой, обоями и ручными назначениями.
  Иконки из паков хранятся как ссылки на пакет и ресурс, поэтому пересборка
  использует свежие изображения после обновления пака. Иконки из файлов
  встраиваются в шаблон как PNG.
- Экспорт в выбранный пользователем `Honor/Themes` с проверкой SHA-256.
  Имя `.hnt` создаётся из названия темы, даты и времени (до секунд);
  при повторном экспорте создаётся новый файл, старые не заменяются.
- Светлое, тёмное или системное оформление с янтарным акцентом.
- Русский и английский языки. При первом запуске выбирается первый поддерживаемый
  язык из системного списка (иначе английский), затем выбор сохраняется независимо от языка системы.
  Выбор языка и оформления доступен через шестерёнку в списке шаблонов и редакторе;
  по умолчанию оформление следует системе.

## Использование

1. Установите APK из [последнего релиза](https://github.com/ToLiveDevelop/Icon-Foundry/releases/latest).
   Android запросит разрешение на установку из выбранного источника.
2. Откройте шаблон или создайте новую тему. Выберите один или несколько
   паков-основ и название. Порядок паков меняется перетаскиванием за «≡».
   Имя файла формируется автоматически.
3. Настройте обложку, состав, форму и ручные назначения. При желании
   добавьте свои обои: одно изображение используется для рабочего стола
   и экрана блокировки.
4. В системном диалоге предоставьте доступ к существующему каталогу
   `Внутренняя память → Honor → Themes`.
5. Нажмите **Создать тему**. После записи `.hnt` автоматически сохраняется
   шаблон. Существующий шаблон обновляется; флажок **Сохранить как новый
   шаблон** создаёт отдельную запись.
6. Откройте штатные **Темы** HONOR и примените созданную тему вручную.

**Важно:** для исправления серого фона иконок в стеке папки нужно применить
тему целиком, не только иконки. При полном применении «Темы» HONOR могут
подставить запасные обои, если своих обоев в файле нет. Отсутствие обоев
в `.hnt` не гарантирует сохранение текущих. Приложение само тему или обои
не применяет и текущие системные обои не читает.

## Совместимость и ограничения

Минимальная версия Android — 15 (API 35), целевая — API 37. Формат исследован
по реальным темам и установленным приложениям HONOR; поведение других версий
лаунчера может отличаться. Проект не связан с HONOR и не заявляет официального
соответствия дизайн-гайдлайнам MagicOS.

Поддерживаются XML из ресурсов и assets, `drawable.xml`, `drawable`/`mipmap`,
растровые, векторные и адаптивные иконки. Некорректный XML пака или исчезнувшее
ручное назначение вызывают явную ошибку, а не скрытую подмену изображения.
Не все Android-иконпаки предоставляют совместимый интерфейс.

Динамический календарь фиксируется на дне загрузки пака, часы и анимации
становятся статичными. Подложки самого иконпака не воспроизводятся.
Экспортируются ярлыки текущего пользовательского профиля; рабочие и
клонированные профили отдельно не перечисляются.

В полном режиме экспортируются сопоставления `appfilter`, а не все
альтернативные изображения без привязки к приложению. Подхватывание иконок
для будущих установок зависит от лаунчера. Ручные назначения и исключения
имеют приоритет. Разные ярлыки одного приложения могут иметь отдельные иконки.

При нескольких паках-основах иконка приложения берётся из первого по порядку
пака, где она есть. В полном режиме сопоставления объединяются по приоритету:
сначала все из первого пака, затем только отсутствующие в нём из второго и т. д.
Ручные назначения важнее порядка паков. Если пак из шаблона удалён с телефона,
тема собирается из оставшихся, а приложение сообщает об отсутствующих.

Маска не меняет PNG из пака. Её размер оценивается по медиане видимых границ
до 48 уникальных сопоставленных иконок с порогом альфа 128. У неоднородных
паков это оценка общего размера, а не гарантия одинаковой воспринимаемой
площади. Дополнительная нормализация лаунчером требует проверки после
ручного применения.

### Накладка поверх иконки

В карточке «Накладка поверх иконок» можно выбрать квадратный PNG с прозрачным фоном и центром:
рамку, блики или декор. Рекомендуется 192 × 192 px. Другие размеры приводятся
к 192 × 192 без обрезки. Рисунок размещается на всём холсте и не подгоняется
автоматически под видимые границы конкретного пака: используйте предпросмотр.
Сплошные непрозрачные и полностью пустые файлы отклоняются.

`icon_mask.png` обрезает иконку, а `icon_border.png` накладывается сверху.
Прозрачные пиксели накладки показывают исходную иконку; непрозрачные закрывают её.
Выбор **Только системные иконки без замены** оставляет иконпаки и назначения
из файлов нетронутыми. В режиме **Все иконки, включая паки и файлы** накладка
дополнительно впекается в экспортируемые PNG и показывается на автообложке.
Форма обрезки по-прежнему действует только на иконки без замены.

Накладка также видна в списке приложений на системных иконках при включённой
галочке «Системная иконка». В режиме для всех иконок она показывается
и на заменах из паков/файлов, в каталоге ручного выбора и при импорте файла.
Исходный файл сохраняется без накладки: её можно заменить или убрать позже.

Файл накладки и выбранный режим сохраняются в шаблоне; исходный PNG после
импорта не нужен. Поддержка `icon_border.png` и порядок композиции проверены
по framework подключённого HONOR: `HwResourcesImpl` загружает верхний слой,
а `IconBitmapUtils.composeIcon` рисует его после маски и исходной иконки.
Фактическое оформление системных иконок зависит от версии и настроек лаунчера,
в том числе его обработки прозрачных иконок. Темы для проверки автоматически
не применяются.

Шаблоны и черновик хранятся локально и сохраняются при обновлении с тем же
ключом подписи. Удаление приложения или очистка данных удаляют их.
Старое вручную заданное имя файла в шаблоне больше не используется; остальные
параметры, ручные назначения и вложенные изображения сохраняются.

### Обновление темы в приложении HONOR

С версии 1.11 Icon Foundry проверяет `.hnt` в выбранной папке экспорта и читает
название и дизайнера из метаданных. Если тема с таким названием и дизайнером
`Icon Foundry by ToLive` уже есть, к названию добавится версия: например,
`Premium Icons v2`. Новое имя показывается в результате экспорта и записывается
в `.hnt`; название в шаблоне остаётся тем, которое ввёл пользователь.

Файл получает имя вида `Premium Icons v2_2026-10-29_15-55-19.hnt` (без
миллисекунд; если такое имя занято, добавляется `_2`, `_3`…). Недопустимые
файловые символы заменяются на `_`, длинная основа сокращается. Существующие
файлы не заменяются; старые `.hnt` автоматически не удаляются.

Замена `.hnt` не гарантирует обновления его записи в «Темах»: приложение HONOR
ведёт собственную базу установленных тем и распакованный кэш. В исследованной
версии совпадение названия и дизайнера считается той же темой; смена только
имени файла поэтому недостаточна. Очистка кэша не обязательно удаляет запись
из базы. Публичный поддерживаемый интерфейс принудительного пересканирования
для сторонних приложений не найден. Icon Foundry задаёт новой теме уникальное
видимое название, чтобы HONOR мог показать её отдельной записью; это не
обновление прежней записи.

Системный список установленных тем сторонним приложениям недоступен. Поэтому
автоверсия основывается на `.hnt`, найденных в выбранной папке, а не на базе
приложения «Темы». Если запись в HONOR осталась, а её файл удалён или перемещён,
Icon Foundry не сможет её обнаружить; удаление записи в HONOR также может
удалить соответствующий `.hnt`. После создания выберите и примените нужную
тему вручную.

Автоматическое повышение внутренней версии темы намеренно не включено:
в исследованном коде HONOR путь обновления удаляет архив предыдущей версии,
и безопасность замены по тому же пути не подтверждена. Проверка отдельной
временной темы не подтвердила надёжное обнаружение нового файла через интерфейс.
Icon Foundry не удаляет записи в «Темах», не очищает их данные и не применяет
тему автоматически.

Коммерческие иконки предназначены для личного использования. Приложение
не содержит изображения из сторонних паков или официальных тем. Не
распространяйте созданные темы без разрешения правообладателей.

## Сборка

Нужны JDK 25, Android SDK Platform 37 и настроенный `ANDROID_HOME` либо
локальный `local.properties` с `sdk.dir`. Gradle Wrapper включён в репозиторий.

```powershell
.\gradlew.bat --no-daemon :app:assembleDebug :app:lintDebug
```

APK: `app\build\outputs\apk\debug\app-debug.apk`.

Текущие публикуемые APK — debug-сборки, подписанные одним локальным
отладочным ключом. Самостоятельная сборка на другой машине получит другой
ключ и не установится поверх опубликованной без удаления приложения.
Ключи подписи в репозиторий не включаются.

### Проверки на устройстве

```powershell
.\tools\device-test.ps1
```

Нужны авторизованный ADB, установленный Premium Icons, образец темы
`/sdcard/Dev/Luminescence.hnt` (путь меняется параметром `PhoneReference`),
паки для межпаковых и геометрических проверок и ранее предоставленный
приложению доступ к `Honor/Themes`. Runner использует специфичные для
исследованного HONOR проверки, включая Contacts/Dialer. Это интеграционный
набор для подготовленного устройства, а не универсальный эмуляторный тест.

Скрипт собирает APK, запускает lint, устанавливает приложение и тестовый APK,
проверяет экспорт через SAF и удаляет собственные временные темы, не применяя
их. Тестовый пакет после проверки можно удалить:
`adb uninstall dev.iconmanager.test`. Пользовательские темы не заменяются.

## Формат экспорта

Внешний ZIP `.hnt`: `description.xml` с корнем `HnTheme`, вложенный ZIP `icons`,
каталог `preview/`, обложки `cover.jpg` и `preview_icons_0.jpg` 720×1280,
миниатюра `icon_small.jpg` 180×320.

В `author` и `designer` указывается `Icon Foundry by ToLive`. Описание:
«На основе иконпака „название пака“. Права на иконки принадлежат разработчику
иконпака. Только для персонального использования». Для нескольких паков
перечисляются все: «На основе иконпаков „A“, „B“…». Имя разработчика пака
не угадывается: стандартного Android-поля для него нет.

В `icons` — плоские `<package-or-activity>.png` 192×192 и необязательная
`icon_mask.png`. Для исправления стека добавляется ZIP-модуль
`com.hihonor.android.launcher` с `theme.xml` и `night/theme.xml`, задающими
только прозрачный цвет `magic_gray_4`. Он также влияет на фон стандартного
неизвестного ярлыка в ночном режиме.

Явно выбранные обои добавляются как `wallpaper/home_wallpaper_0.jpg` и
`wallpaper/unlock_wallpaper_0.jpg`. JPEG ограничен длинной стороной 3200 px,
пропорции сохраняются. Обрезку под экран выполняют «Темы». Модули блокировки,
AOD, шрифты и настройки сторонних тем не копируются.

## Публикация версий

Для каждой законченной версии повышаются `versionCode` / `versionName`,
изменения проверяются, коммитятся и отправляются в этот репозиторий.
Тег `v<versionName>` соответствует GitHub Release с локально собранным
`Icon-Foundry.apk`. Сохраняйте ключ подписи для совместимых обновлений.

Посадочная страница находится в `docs/`. Workflow
`.github/workflows/pages.yml` публикует её в GitHub Pages при изменениях
в `main`. Настройки Pages должны использовать **GitHub Actions**.

Добавлены безопасные отступы 8 dp вокруг превью формы и явный `FIT_CENTER`.
Изображение целиком помещается внутри области просмотра; геометрия маски
и экспортируемые иконки при этом не меняются.

### 1.8

Добавлены иконки из файлов: предпросмотр перед назначением, сохранение
пропорций и прозрачности, собственная копия PNG 192×192 и встраивание в шаблон.
Файловые назначения работают в обоих режимах экспорта; исходное изображение
после импорта не требуется. Иконки из установленных паков по-прежнему остаются
ссылками на ресурсы. Добавлена некоммерческая лицензия и пояснения об ограничениях
обновления записей в «Темах» HONOR; рискованная автоматическая смена версии
метаданных не включена.

### 1.9

Убран дублирующий нижний лоадер: над кнопкой остаётся только центрированная
подпись об автосохранении черновика, загрузка показывается в popup или скелетоне
выбора пака. Пояснения сокращены с сохранением ограничений. Имя файла больше
не запрашивается и не хранится в параметрах шаблона: каждый экспорт получает
название с датой и временем. Название самой темы не меняется. Обновлены авторство
и описание темы с указанием базового иконпака и персонального использования.

### 1.10

Кнопка «Не включать обои» заменена на «Убрать обои», которая показывается только
после добавления обоев. «Продолжить черновик» появляется в списке шаблонов только
при изменениях, не сохранённых в шаблон. Дата в имени файла и названии шаблона —
без миллисекунд.

### 1.11

Перед экспортом читаются метаданные `.hnt` из выбранной папки. При совпадении
названия темы Icon Foundry новая тема автоматически получает `v2`, `v3` и т. д.
Уникальное имя используется в `.hnt`, а введённое название сохраняется в шаблоне.
Это проверяет только локальные файлы экспорта и не запрашивает внутреннюю базу
установленных тем HONOR.

### 1.12

Можно выбрать до 10 паков-основ и упорядочить их перетаскиванием (или действиями
специальных возможностей). Для каждого приложения используется самый приоритетный
пак, где есть его иконка; полный режим объединяет паки по приоритету без дублей.
С одним паком поведение и формат шаблона прежние. Обложка, описание темы, выбор
иконок и оценка размера маски учитывают все выбранные паки.

### 1.13

В ручном выборе иконки при нескольких паках-основах слева появились вкладки
с иконками паков; поиск ищет сразу по всем пакам шаблона, а вкладка переносит
к результатам своего пака. Кнопка «Выбрать другой иконпак» открывает пак вне
шаблона, после чего доступны «Вернуть иконпак(и) шаблона» и «Выбрать другой».
Окно загрузки шаблона закрывается только после отрисовки списка паков.

### 1.14

В списке приложений добавлена галочка «Системная иконка»: вместо заглушки
показывается иконка системы; выбор сохраняется в шаблоне. В выборе иконки
кнопки «Другой иконпак» и «Из файла» стоят рядом, счётчик найденных убран,
«Оставить системную» и «Из иконпака шаблона» показываются, только когда
они что-то меняют. «Использовать автообложку» видна только для выбранной
обложки, «Выбрать обои» без обоев занимает всю ширину, кнопка каталога после
выбора называется «Изменить папку». Новая тема по умолчанию использует маску
«Скруглённый квадрат».

### 1.15

Новая версия названия берётся как максимальная среди готовых тем + 1: при
Mello v2 и Mello v4 создаётся Mello v5. В выборе иконки строка поиска
отделена от кнопок «Другой иконпак» / «Из файла». Подпись «Черновик
сохраняется автоматически» осталась только в редакторе.

### 1.16

Иконпаки читают appfilter.xml и drawable.xml из res/xml, а assets — только если
в res/xml нет рабочих записей.
Раньше шаблонные заглушки в assets (например, у MATION) скрывали полный
каталог пака, и было видно всего несколько иконок. Паки шаблона загружаются
параллельно, поэтому шаблоны с несколькими паками открываются быстрее.

### 1.17

Добавлены настройки оформления (как в системе по умолчанию, светлое, тёмное)
и языка (русский, английский). При первом запуске выбирается системный язык,
если он поддерживается, иначе английский; дальнейшие изменения — в настройках.
Смена настроек сохраняет черновик и открытый экран редактора.

Добавлены PNG-накладки поверх иконок с предпросмотром, проверкой прозрачности,
сохранением внутри шаблона и выбором области действия: только системные
иконки без замены или все иконки, включая паки и файлы.

### 1.18

Настройки получили новый экран с плитками оформления, выбором языка с отметкой
и закреплённой кнопкой применения. Кнопка настроек теперь с шестерёнкой
и отступом от «Шаблонов».

Пустые разделы обложки, обоев и PNG-накладки свёрнуты; карточка накладки
следует сразу за обоями. Их можно раскрыть
нажатием на заголовок. При открытии сохранённого шаблона заполненные разделы
сразу раскрыты. Сворачивание не меняет содержимое шаблона.

### 1.20

Накладка отображается на системных иконках в списке приложений, если включена
галочка «Системная иконка». В режиме для всех иконок она также видна на иконках
из паков и файлов, в ручном выборе и при импорте изображения. Предпросмотры
учитывают замену или удаление накладки, не изменяя исходные изображения.

### 1.21

Вместо выпадающего списка форм — окно с шестью системными иконками на фоне
обоев шаблона. При отсутствии обоев используется нейтральный градиент только
для предпросмотра: он не сохраняется в тему и не меняет обои телефона.
Сначала выбираются приложения без замены по алфавиту; если их меньше шести,
добавляются системные иконки остальных приложений без повторов.

Формы представлены плитками с силуэтами; добавлены сердце, звезда,
шестиугольник и скруглённый пятиугольник. Вместо квадрата — квадрат со скруглением
вдвое меньше, чем у обычного скруглённого квадрата. Предпросмотр учитывает размер маски
и накладку. Изменения сохраняются только кнопкой «Применить», закрытие окна
оставляет прежнюю форму. Идентификаторы форм совместимы со старыми шаблонами;
сохранённый «Квадрат» теперь также отображается с лёгким скруглением.
