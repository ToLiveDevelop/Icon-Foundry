# Icon Foundry

**Ваши иконки. Ваша тема.**

Android-приложение, которое превращает установленные иконпаки в темы `.hnt`
для штатного лаунчера HONOR MagicOS 10+. Android 15+, без root, рекламы,
сетевого доступа и разрешения на всю память.

[Сайт](https://tolivedevelop.github.io/Icon-Foundry/) ·
[Скачать APK](https://github.com/ToLiveDevelop/Icon-Foundry/releases/latest) ·
[Сообщить о проблеме](https://github.com/ToLiveDevelop/Icon-Foundry/issues)

## Возможности

- Обнаружение установленных иконпаков с `appfilter.xml`.
- До 10 паков-основ с приоритетом, который задаётся перетаскиванием:
  каждое приложение получает иконку из самого верхнего пака, где она есть.
- Ручная замена иконок, в том числе из других установленных паков. При нескольких
  паках-основах слева есть вкладки-иконки паков, а поиск идёт сразу по всем.
- Иконки из файлов с предпросмотром перед назначением. Копии изображений
  сохраняются внутри шаблона, исходные файлы после импорта не нужны.
- Экспорт только установленных приложений или всех сопоставлений пака,
  включая будущие установки.
- Приложения, установленные только в рабочем профиле (например, Island), и
  ярлык Parallel Space (ключ темы `com.hihonor.parallelspace`) тоже
  попадают в список и получают иконки. Приватное пространство Android недоступно
  обычным приложениям.
- Маски для системных иконок: готовые формы, редактор скруглений или собственная
  квадратная PNG-маска. В PNG альфа-канал задаёт силуэт: непрозрачные области
  сохраняют иконку, прозрачные обрезают. Предпросмотр — на шести системных
  иконках поверх обоев шаблона или градиента; размер учитывает типичный размер
  иконок пака. Ограничение HONOR: некоторые системные поверхности, включая
  «Недавние», могут применять глобальный `icon_mask.png` и к иконкам из пака.
  Формат `.hnt` не предоставляет отдельного исключения для сопоставленных иконок.
- Накладка поверх иконки из прозрачного PNG: только для системных иконок
  без замены либо для всех иконок. Есть предпросмотр; файл хранится в шаблоне.
- Фильтры системных иконок: цветокоррекция и позиция с изменяемым порядком
  и предпросмотром на шести иконках.
- На вкладке **Стиль** закреплённое превью показывает три системные иконки
  и три замены из паков. Фон превью заполняет всю доступную область без полос
  по краям; изменение настроек не перекрывает иконки индикатором загрузки.
  Под превью вкладки **Фон под иконками**, **Накладка**, **Параметры иконок**
  и **Фильтры**; форма, углы, масштабы и обрезка редактируются здесь же,
  без отдельных окон подтверждения, и сразу сохраняются и обновляют сцену.
  Выбор формы сохраняет сетку силуэтов и отдельные вкладки редактора углов
  и PNG-маски. Фон и накладка больше не сворачиваются, справка доступна рядом
  с кнопками выбора. На вкладке фильтров оба ряда превью показывают системные
  иконки; при выходе из неё второй ряд снова показывает иконки паков.
  В горизонтальной ориентации превью закреплено слева от настроек.
  Если установленных примеров не хватает, системный ряд дополняется исходными
  иконками приложений, а ряд паков — иконками каталога (без искусственных дублей).
- Обложка с обрезкой 9:16 или автообложка из 12 разных иконок:
  популярные приложения и алфавитное заполнение недостающих мест.
- Необязательные пользовательские обои для рабочего стола и блокировки.
- Шаблоны с параметрами, обложкой, обоями и ручными назначениями.
  Иконки из паков хранятся как ссылки на пакет и ресурс, поэтому пересборка
  использует свежие изображения после обновления пака. Иконки из файлов
  встраиваются в шаблон как PNG. В «Настройках» можно сохранить и восстановить
  полный файл резервной копии шаблонов.
- Экспорт в выбранный пользователем `Honor/Themes` с проверкой SHA-256.
  Имя `.hnt` создаётся из названия темы, даты и времени (до секунд);
  при повторном экспорте создаётся новый файл, старые не заменяются.
- Светлое, тёмное или системное оформление с янтарным акцентом.
- Русский и английский языки. При первом запуске выбирается первый поддерживаемый
  язык из системного списка (иначе английский), затем выбор сохраняется независимо от языка системы.
  Выбор языка и оформления доступен через шестерёнку в списке шаблонов и редакторе;
  по умолчанию оформление следует системе.

## Использование

1. Установите APK из [последнего релиза](https://github.com/ToLiveDevelop/Icon-Foundry/releases/latest).
   Android запросит разрешение на установку из выбранного источника.
2. Откройте шаблон или создайте новую тему. Выберите один или несколько
   паков-основ и название. Порядок паков меняется перетаскиванием за «≡».
   Имя файла формируется автоматически.
3. Настройте обложку, состав, форму и ручные назначения. При желании
   добавьте свои обои: одно изображение используется для рабочего стола
   и экрана блокировки.
4. В системном диалоге предоставьте доступ к существующему каталогу
   `Внутренняя память → Honor → Themes`.
5. Нажмите **Создать тему**. После записи `.hnt` автоматически сохраняется
   шаблон. Существующий шаблон обновляется; флажок **Сохранить как новый
   шаблон** создаёт отдельную запись.
6. Откройте штатные **Темы** HONOR и примените созданную тему вручную.

### Резервная копия шаблонов

Откройте ⚙️ **Настройки** и выберите **Сохранить файл бэкапа**. JSON-файл
содержит все шаблоны, включая обложки, обои, пользовательские иконки и PNG-маски.
Чтобы перенести их на другое устройство, скопируйте файл и выберите
**Восстановить из бэкапа**. Файл проверяется целиком до изменения хранилища;
повреждённый или неподдерживаемый бэкап не меняет шаблоны. При восстановлении
записи объединяются по ID: существующие шаблоны, в том числе с совпавшими ID,
остаются без изменений, добавляются только новые для этого устройства.

Файл включает контрольную сумму SHA-256 и ограничен размером 64 МиБ.
Привязка к папке экспорта и локальные пути изображений не переносятся;
после восстановления выберите папку для экспорта заново. Для иконок из паков
соответствующие паки должны быть установлены на новом устройстве.

**Важно:** для исправления серого фона иконок в стеке папки нужно применить
тему целиком, не только иконки. При полном применении «Темы» HONOR могут
подставить запасные обои, если своих обоев в файле нет. Отсутствие обоев
в `.hnt` не гарантирует сохранение текущих. Приложение само тему или обои
не применяет и текущие системные обои не читает.

Для сохранения стеклянного фона маленькой папки при применении только иконок
тема содержит настройки поддержки подсветки HONOR, но не подменяет изображения
фона папки. Работа проверена на подключённом устройстве; другие версии лаунчера
могут обрабатывать эти настройки иначе.

## Совместимость и ограничения

Минимальная версия Android — 15 (API 35), целевая — API 37. Формат исследован
по реальным темам и установленным приложениям HONOR; поведение других версий
лаунчера может отличаться. Проект не связан с HONOR и не заявляет официального
соответствия дизайн-гайдлайнам MagicOS.

Поддерживаются XML из ресурсов и assets, `drawable.xml`, `drawable`/`mipmap`,
растровые, векторные и адаптивные иконки. Некорректный XML пака или исчезнувшее
ручное назначение вызывают явную ошибку, а не скрытую подмену изображения.
Не все Android-иконпаки предоставляют совместимый интерфейс.

Динамический календарь фиксируется на дне загрузки пака, часы и анимации
становятся статичными. Подложки самого иконпака не воспроизводятся.
Экспортируются ярлыки текущего пользовательского профиля; рабочие и
клонированные профили отдельно не перечисляются.

В полном режиме экспортируются сопоставления `appfilter`, а не все
альтернативные изображения без привязки к приложению. Подхватывание иконок
для будущих установок зависит от лаунчера. Ручные назначения и исключения
имеют приоритет. Разные ярлыки одного приложения могут иметь отдельные иконки.

HONOR сначала ищет `<класс activity>.png`, затем `<пакет>.png`, причём файл
activity общий для всех приложений с таким именем класса. Поэтому отдельный
файл activity пишется только для ярлыка, чья иконка отличается от иконки
пакета. Если класс совпадает у разных приложений с разными иконками
(например, `PeopleActivity` у HONOR Contacts и Google Contacts), файл класса
не создаётся, и ярлык получает иконку своего пакета — без ошибки экспорта.

При нескольких паках-основах иконка приложения берётся из первого по порядку
пака, где она есть. В полном режиме сопоставления объединяются по приоритету:
сначала все из первого пака, затем только отсутствующие в нём из второго и т. д.
Ручные назначения важнее порядка паков. Если пак из шаблона удалён с телефона,
тема собирается из оставшихся, а приложение сообщает об отсутствующих.

Разрешение экспорта выбирается отдельно в строке каждого пака:
**Исходный / 256 / 192 / 128 / 96 px**. Кнопка показывает краткую подпись
«Разрешение: исходное» или «Разрешение: 256 px» в одну строку.
Круглая кнопка с корзиной удаляет пак из набора.
По умолчанию используется преобладающий (самый частый) исходный размер иконок
из `appfilter` этого пака. В объединённом
наборе PNG могут иметь разные размеры: второстепенный пак больше не увеличивает
разрешение всего набора. Это относится и к старым шаблонам без настройки размера.
Единичные нестандартные ресурсы
(например, 256 × 275 в паке 256 × 256) не меняют разрешение. Ручные
назначения из выбранных паков используют размер своего пака-источника.
Отдельные PNG, назначения из паков вне набора и обработанные системные иконки
вписываются в максимальный выбранный холст. Фиксированный размер может увеличить
маленький исходник, но не добавляет детализации. Эффективное разрешение показывается
в «Параметрах иконок».
Размер определяется по заголовкам уникальных ресурсов, без загрузки
полных изображений, и кешируется на время работы с загруженным паком.
Общие `icon_mask.png`, `icon_border.png` и `icon_background.png` используют
максимальный выбранный квадратный холст. В режиме «Все» слои вписываются
в размер каждой иконки. Настройки сохраняются в черновике и шаблоне и следуют
за паком при перестановке. Векторные иконки поддерживают как минимум
192 px; растровые ресурсы учитываются в исходных пикселях без поправки на DPI.
Предпросмотр использует уменьшенные копии с теми же пропорциями и масштабами.
Большое исходное разрешение увеличивает время сборки и размер темы.
После экспорта показывается фактический размер файла. При превышении 290 МиБ
появляется предупреждение: на проверенном HONOR приложение «Темы» не показывает
архивы около 300 МБ и больше. Порог приблизительный и может зависеть от прошивки;
экспорт не блокируется. Уменьшите размеры второстепенных паков или выберите
только установленные приложения. Тема не применяется автоматически.

Масштаб иконок (50–150%) применяется к иконкам из паков и назначенным вручную:
рисунок масштабируется относительно центра своего холста. Ниже 100% остаются
прозрачные поля, поэтому фон и его рамка видны; выше 100% края обрезаются.
Накладка и фон в режиме «Все» применяются после масштабирования. Системные
иконки без замены HONOR масштабирует сам по форме — настройка на них не влияет.
Масштаб виден в предпросмотре, списке приложений, выборе иконки и автообложке.
Ползунок находится в окне настройки фона, а не в «Параметрах иконок».
После выбора PNG это окно открывается автоматически; для выбранного фона
кнопка **Настройки фона** открывает его повторно. Два ряда по три разных
приложения показывают системные иконки без замены и иконки из пака.
Масштабы фона и иконок регулируются независимо, со стрелками для шага ±1.
Настройки сохраняются кнопкой **Использовать фон**; закрытие окна отменяет
изменения. Если подходящих приложений меньше трёх, пустые места отмечаются явно.

Маска не меняет PNG из пака. Её размер оценивается по медиане видимых границ
до 48 уникальных сопоставленных иконок с порогом альфа 128. У неоднородных
паков это оценка общего размера, а не гарантия одинаковой воспринимаемой
площади. Дополнительная нормализация лаунчером требует проверки после
ручного применения.

### Накладка поверх иконки

В карточке «Накладка поверх иконок» можно выбрать квадратный PNG с прозрачным фоном и центром:
рамку, блики или декор. Исходное разрешение PNG (до 4096 × 4096 px) сохраняется
в шаблоне; при экспорте слои приводятся к общему разрешению выбранных паков.
Рисунок размещается на всём холсте и не подгоняется
автоматически под видимые границы конкретного пака: используйте предпросмотр.
Масштаб накладки настраивается от 50 до 150% в окне выбора формы, только если
накладка выбрана. Результат сразу виден на шести иконках; «Применить» сохраняет
форму и масштаб, закрытие окна отменяет изменения. Для PNG с большими
прозрачными полями увеличьте масштаб (например, до 120%). Рисунок за пределами
холста обрезается. Значение сохраняется в шаблоне и одинаково используется
в предпросмотре, автообложке, экспортируемых иконках и `icon_border.png`.
Старые шаблоны используют 100%; исходный PNG не меняется.
Сплошные непрозрачные и полностью пустые файлы отклоняются (проверяется исходный
PNG; при масштабе до 150% накладка может закрыть весь холст).

Переключатель **Обрезать накладку по форме** (включён по умолчанию) скрывает
части накладки за пределами формы: `icon_border.png` обрезается по маске,
а запечённая в иконки пака накладка — по контуру каждой иконки.

`icon_mask.png` обрезает иконку, а `icon_border.png` накладывается сверху.
Прозрачные пиксели накладки показывают исходную иконку; непрозрачные закрывают её.
Выбор **Только системные иконки без замены** оставляет иконпаки и назначения
из файлов нетронутыми. В режиме **Все иконки, включая паки и файлы** накладка
дополнительно впекается в экспортируемые PNG и показывается на автообложке.
Форма обрезки по-прежнему действует только на иконки без замены.

Накладка также видна в списке приложений на системных иконках при включённой
галочке «Показывать системные иконки». В режиме для всех иконок она показывается
и на заменах из паков/файлов, в каталоге ручного выбора и при импорте файла.
Исходный файл сохраняется без накладки: её можно заменить или убрать позже.

Файл накладки и выбранный режим сохраняются в шаблоне; исходный PNG после
импорта не нужен. Поддержка `icon_border.png` и порядок композиции проверены
по framework подключённого HONOR: `HwResourcesImpl` загружает верхний слой,
а `IconBitmapUtils.composeIcon` рисует его после маски и исходной иконки.
Фактическое оформление системных иконок зависит от версии и настроек лаунчера,
в том числе его обработки прозрачных иконок. Темы для проверки автоматически
не применяются.

Шаблоны и черновик хранятся локально и сохраняются при обновлении с тем же
ключом подписи. Удаление приложения или очистка данных удаляют их.
Старое вручную заданное имя файла в шаблоне больше не используется; остальные
параметры, ручные назначения и вложенные изображения сохраняются.

### Форма и редактор формы

Окно выбора формы содержит вкладки «Готовые формы», «Редактор» и «Из файла». В редакторе
четыре ползунка задают скругление углов (левый верхний, правый верхний,
правый нижний, левый нижний) от 0% (острый угол) до 100% (половина стороны);
100% во всех углах дают круг. Результат становится маской `icon_mask.png`
и сохраняется в шаблоне.

На вкладке «Из файла» можно загрузить квадратный PNG. Силуэт задаёт альфа-канал:
непрозрачные пиксели сохраняют изображение иконки, прозрачные обрезают; RGB-цвет
маски игнорируется. Маска автоматически масштабируется до разрешения экспорта, с учётом
типичного размера иконок выбранного пака. Её предпросмотр виден на системных
иконках в сцене выбора формы. PNG встраивается в шаблон; при экспорте
генерируется штатный `icon_mask.png`.

### Фон под иконками

Отдельная карточка принимает квадратный PNG (до 4096 × 4096 px),
в том числе полностью непрозрачный. Фон рисуется **под** иконкой, поэтому
виден в её прозрачных участках, но не заменяет уже нарисованный фон самой иконки.
По умолчанию он применяется только к системным иконкам без замены; режим
«Все иконки» также добавляет его к иконкам паков и файлам при экспорте.

В окне выбора формы есть масштаб фона 50–150% и независимый переключатель
«Обрезать фон по форме» (по умолчанию включён). Предпросмотр на обоях обновляется
сразу; «Применить» сохраняет настройки, закрытие окна отменяет изменения.
В режиме «Все» фон виден в каталоге ручного выбора иконки, предпросмотре файла,
списке приложений и автообложке. Масштаб, режим, обрезка и исходный PNG
сохраняются в шаблоне. Сами иконки паков не обрезаются.

Экспорт записывает фон в `icon_background.png` внутри ZIP-модуля `icons`.
Если накладка не выбрана, добавляется прозрачный `icon_border.png`: старый путь
загрузки фоновых изображений в прошивке HONOR требует наличия этого слоя.
Тема не применяется автоматически; фактический вид системных иконок также
зависит от обработки прозрачности и настроек лаунчера.

### Фильтры системных иконок

Кнопка **Фильтры** в «Параметрах иконок» открывает цепочку фильтров для
установленных приложений, у которых нет иконки в паке и не выбрана иконка
вручную (из другого пака или файла). Фильтры выполняются сверху вниз; их можно
добавлять (до 10), удалять и переставлять стрелками. **Цветокоррекция** включает
яркость, контраст, насыщенность, красный, зелёный и синий каналы, «чёрный»
(сдвиг точки чёрного: плюс углубляет тени, минус высветляет) и непрозрачность.
**Позиция** задаёт масштаб 50–150%, смещение по X и Y от −100 до 100% размера
холста и плоский наклон по каждой оси от −45° до 45°. Положительные смещения
направлены вправо и вниз. Фильтр изменяет только иконку; фон, маска и накладка
остаются на месте. Части иконки за границами холста или маски обрезаются.
Все ползунки имеют стрелки для шага ±1.

Предпросмотр закреплён над списком и показывает шесть таких иконок с текущей
формой, фоном и накладкой. «Применить фильтры» сохраняет цепочку в шаблоне,
закрытие окна отменяет изменения.

HONOR применяет `icon_mask`, `icon_background` и `icon_border` только к иконкам,
которых нет в теме, и не умеет перекрашивать их. Поэтому при активных фильтрах
системная иконка рендерится в приложении: фильтры → форма → накладка → фон,
и сохраняется в тему готовым PNG в разрешении экспорта. В режиме «Все иконки
паков» так обрабатываются только установленные приложения: у будущих приложений
системной иконки ещё нет, и они получат обычную маску темы без фильтров.
Нейтральные фильтры ничего не добавляют в тему.

### Обновление темы в приложении HONOR

С версии 1.11 Icon Foundry проверяет `.hnt` в выбранной папке экспорта и читает
название и дизайнера из метаданных. Если тема с таким названием и дизайнером
`Icon Foundry by ToLive` уже есть, к названию добавится версия: например,
`Premium Icons v2`. Новое имя показывается в результате экспорта и записывается
в `.hnt`; название в шаблоне остаётся тем, которое ввёл пользователь.

Файл получает имя вида `Premium Icons v2_2026-10-29_15-55-19.hnt` (без
миллисекунд; если такое имя занято, добавляется `_2`, `_3`…). Недопустимые
файловые символы заменяются на `_`, длинная основа сокращается. Существующие
файлы не заменяются; старые `.hnt` автоматически не удаляются.

Замена `.hnt` не гарантирует обновления его записи в «Темах»: приложение HONOR
ведёт собственную базу установленных тем и распакованный кэш. В исследованной
версии совпадение названия и дизайнера считается той же темой; смена только
имени файла поэтому недостаточна. Очистка кэша не обязательно удаляет запись
из базы. Публичный поддерживаемый интерфейс принудительного пересканирования
для сторонних приложений не найден. Icon Foundry задаёт новой теме уникальное
видимое название, чтобы HONOR мог показать её отдельной записью; это не
обновление прежней записи.

Системный список установленных тем сторонним приложениям недоступен. Поэтому
автоверсия основывается на `.hnt`, найденных в выбранной папке, а не на базе
приложения «Темы». Если запись в HONOR осталась, а её файл удалён или перемещён,
Icon Foundry не сможет её обнаружить; удаление записи в HONOR также может
удалить соответствующий `.hnt`. После создания выберите и примените нужную
тему вручную.

Автоматическое повышение внутренней версии темы намеренно не включено:
в исследованном коде HONOR путь обновления удаляет архив предыдущей версии,
и безопасность замены по тому же пути не подтверждена. Проверка отдельной
временной темы не подтвердила надёжное обнаружение нового файла через интерфейс.
Icon Foundry не удаляет записи в «Темах», не очищает их данные и не применяет
тему автоматически.

Коммерческие иконки предназначены для личного использования. Приложение
не содержит изображения из сторонних паков или официальных тем. Не
распространяйте созданные темы без разрешения правообладателей.

## Сборка

Нужны JDK 25, Android SDK Platform 37 и настроенный `ANDROID_HOME` либо
локальный `local.properties` с `sdk.dir`. Gradle Wrapper включён в репозиторий.

```powershell
.\gradlew.bat --no-daemon :app:assembleDebug :app:lintDebug
```

APK: `app\build\outputs\apk\debug\app-debug.apk`.

Текущие публикуемые APK — debug-сборки, подписанные одним локальным
отладочным ключом. Самостоятельная сборка на другой машине получит другой
ключ и не установится поверх опубликованной без удаления приложения.
Ключи подписи в репозиторий не включаются.

Для самостоятельных релизных сборок на Windows создайте собственный ключ
(подтвердите личность организации в сертификате; срок действия — например,
25 лет):

```powershell
New-Item -ItemType Directory -Force "$HOME\.gradle" | Out-Null
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -v `
  -keystore "$HOME\.gradle\icon-foundry-release.jks" `
  -alias icon-foundry -keyalg RSA -keysize 3072 -validity 9125
```

`keytool` запросит пароль хранилища и ключа, а также данные сертификата.
Скопируйте четыре значения ниже в `$HOME\.gradle\gradle.properties`
(создайте файл, если его нет); замените путь на ваш абсолютный путь,
используя `/` как разделитель. Не добавляйте этот файл или `.jks` в Git:

```properties
iconFoundryStoreFile=C:/Users/USERNAME/.gradle/icon-foundry-release.jks
iconFoundryStorePassword=YOUR_STORE_PASSWORD
iconFoundryKeyAlias=icon-foundry
iconFoundryKeyPassword=YOUR_KEY_PASSWORD
```

При запросе `:app:assembleRelease` Gradle берёт значения из пользовательского
файла свойств. Если они отсутствуют или указаны не все, сборка релизного APK
будет остановлена, а debug-сборки продолжат работать. Передавать пароль или
файл keystore Copilot не нужно; достаточно сообщить, что локальная настройка
готова и можно собрать релиз. Не теряйте резервную копию `.jks` и пароли:
без них нельзя подписать совместимое обновление. Сертификат собственного
ключа отличается от опубликованного debug-ключа 1.33; сборка с ним не
установится поверх этой версии без удаления приложения.

### Проверки на устройстве

```powershell
.\tools\device-test.ps1
```

Нужны авторизованный ADB, установленный Premium Icons, образец темы
`/sdcard/Dev/Luminescence.hnt` (путь меняется параметром `PhoneReference`),
паки для межпаковых и геометрических проверок и ранее предоставленный
приложению доступ к `Honor/Themes`. Runner использует специфичные для
исследованного HONOR проверки, включая Contacts/Dialer. Это интеграционный
набор для подготовленного устройства, а не универсальный эмуляторный тест.

Для точечных проверок разрешения по пакам, после сборки и установки приложения
и тестового APK:

```powershell
adb shell am instrument -w -e perPackResolutionOnly true dev.iconmanager.test/dev.iconmanager.DeviceTests
```

Нужны Premium Icons и Pressed, доступ к `Honor/Themes` и разблокированный экран.
Проверяются смешанные PNG, эффекты, сохранение настроек, выбор размера в UI,
реальный экспорт через SAF и порог предупреждения. Пользовательский черновик
восстанавливается; временные тестовые темы удаляются без применения.

Скрипт собирает APK, запускает lint, устанавливает приложение и тестовый APK,
проверяет экспорт через SAF и удаляет собственные временные темы, не применяя
их. Тестовый пакет после проверки можно удалить:
`adb uninstall dev.iconmanager.test`. Пользовательские темы не заменяются.

## Формат экспорта

Внешний ZIP `.hnt`: `description.xml` с корнем `HnTheme`, вложенный ZIP `icons`,
каталог `preview/`, обложки `cover.jpg` и `preview_icons_0.jpg` 720×1280,
миниатюра `icon_small.jpg` 180×320.

В `author` и `designer` указывается `Icon Foundry by ToLive`. Описание:
«На основе иконпака „название пака“. Права на иконки принадлежат разработчику
иконпака. Только для персонального использования». Для нескольких паков
перечисляются все: «На основе иконпаков „A“, „B“…». Имя разработчика пака
не угадывается: стандартного Android-поля для него нет.

В `icons` — плоские `<package-or-activity>.png` в преобладающем исходном
разрешении выбранных паков и необязательная
`icon_mask.png`. Для исправления стека добавляется ZIP-модуль
`com.hihonor.android.launcher` с `theme.xml` и `night/theme.xml`, задающими
только прозрачный цвет `magic_gray_4`. Он также влияет на фон стандартного
неизвестного ярлыка в ночном режиме.

Явно выбранные обои добавляются как `wallpaper/home_wallpaper_0.jpg` и
`wallpaper/unlock_wallpaper_0.jpg`. JPEG ограничен длинной стороной 3200 px,
пропорции сохраняются. Обрезку под экран выполняют «Темы». Модули блокировки,
AOD, шрифты и настройки сторонних тем не копируются.

## Публикация версий

Для каждой законченной версии повышаются `versionCode` / `versionName`,
изменения проверяются, коммитятся и отправляются в этот репозиторий.
Тег `v<versionName>` соответствует GitHub Release с локально собранным
`Icon-Foundry.apk`. Сохраняйте ключ подписи для совместимых обновлений.

Посадочная страница находится в `docs/`. Workflow
`.github/workflows/pages.yml` публикует её в GitHub Pages при изменениях
в `main`. Настройки Pages должны использовать **GitHub Actions**.

Пустые разделы обложки, обоев и PNG-накладки свёрнуты; карточка накладки
следует сразу за обоями. Их можно раскрыть
нажатием на заголовок. При открытии сохранённого шаблона заполненные разделы
сразу раскрыты. Сворачивание не меняет содержимое шаблона.

### 1.20

Накладка отображается на системных иконках в списке приложений, если включена
галочка «Системная иконка». В режиме для всех иконок она также видна на иконках
из паков и файлов, в ручном выборе и при импорте изображения. Предпросмотры
учитывают замену или удаление накладки, не изменяя исходные изображения.

### 1.21

Вместо выпадающего списка форм — окно с шестью системными иконками на фоне
обоев шаблона. При отсутствии обоев используется нейтральный градиент только
для предпросмотра: он не сохраняется в тему и не меняет обои телефона.
Сначала выбираются приложения без замены по алфавиту; если их меньше шести,
добавляются системные иконки остальных приложений без повторов.

Формы представлены плитками с силуэтами; добавлены сердце, звезда,
шестиугольник и скруглённый пятиугольник. Вместо квадрата — квадрат со скруглением
вдвое меньше, чем у обычного скруглённого квадрата. Предпросмотр учитывает размер маски
и накладку. Изменения сохраняются только кнопкой «Применить», закрытие окна
оставляет прежнюю форму. Идентификаторы форм совместимы со старыми шаблонами;
сохранённый «Квадрат» теперь также отображается с лёгким скруглением.

### 1.22

Предпросмотры берут иконки из ресурсов самих приложений, а не уже обрезанные
маской применённой темы HONOR. Поэтому форма в окне выбора и на карточке
больше не урезается текущей темой, а системные иконки в назначении
показываются с формой шаблона. Квадрат со слегка скруглёнными углами
называется просто «Квадрат». Проверки, повторявшиеся для каждого PNG
экспорта, теперь считаются один раз.

### 1.23

Домашние лаунчеры (включая P Launcher) больше не предлагаются как иконпаки,
даже если содержат внутренний `appfilter.xml`. Для остальных кандидатов
проверяется наличие сопоставления приложения с существующим ресурсом иконки;
поддержка `res/xml` и запасного `assets/appfilter.xml` сохраняется.
Добавлен масштаб PNG-накладки 50–150% с сохранением в шаблоне,
предпросмотром и применением при экспорте без изменения размера холста 192×192.

### 1.24

Исправлена ошибка «накладка не соответствует требованиям» при масштабе от 140%:
требование прозрачных пикселей проверяется только у исходного PNG.
Добавлен переключатель обрезки накладки по форме и вкладка «Редактор»
с настройкой скругления каждого из четырёх углов.

### 1.25

Добавлен фон под иконками: импорт PNG, отдельный выбор области применения,
масштаб 50–150% и переключатель обрезки в окне выбора формы. Фон отражается
в предпросмотрах, ручном выборе иконок, автообложке и экспортируемой теме;
исходник и настройки сохраняются в шаблоне.

### 1.26

В окно формы добавлена загрузка пользовательской маски из квадратного PNG.
Альфа-канал задаёт силуэт; исходное изображение встраивается в шаблон, а
экспорт включает соответствующий `icon_mask.png`.

### 1.27

Пояснения вынесены из интерфейса в окна справки: у каждого блока есть своя
кнопка «?». Для PNG-маски добавлен масштаб 50–150%, а у всех ползунков
масштаба и углов появились стрелки для точного шага ±1.

### 1.28

Кнопки справки стали менее заметными: приглушённый цвет, меньший значок
и прозрачный фон при сохранении удобной области нажатия. Добавлены отступы
между заголовками со справкой и элементами управления, включая название
темы, фон под иконками, накладку и маску из файла.

### 1.29

Разрешение иконок и служебных слоёв при экспорте автоматически выбирается
по самой большой исходной иконке из `appfilter` выбранных паков и ручных
назначений; картинки предпросмотра в каталоге не учитываются. Новые PNG
накладок, фона и масок сохраняются без уменьшения до 192 px; старые шаблоны
остаются совместимыми. Для восстановления деталей ранее уменьшенных PNG
нужно загрузить их исходные файлы заново. У вкладок «Готовые формы»,
«Редактор» и «Из файла» убрана тень, в том числе при нажатии.

### 1.30

Добавлен ползунок «Масштаб иконок» (50–150%, стрелки ±1) для иконок из паков
и ручных назначений; он влияет на экспорт, обложку и все предпросмотры.
Разрешение экспорта теперь определяется по преобладающему размеру иконок пака,
а не по максимальному: единичные нестандартные ресурсы больше не увеличивают
холст (Pressed — 256 × 256). Разрешение показывается в «Параметрах темы».
Исправлен показ ошибок со знаком «%» в тексте. Убрана ошибка экспорта
«Формат HONOR не различает общую activity»: приложения с одинаковым классом
activity (HONOR Contacts и Google Contacts) теперь получают иконки по пакету.
Добавлен отступ между предпросмотром масштаба иконки и стрелками ползунка.
Проверено, что фон маленькой папки (`portal_ring_inner_holo.png` и его тёмный
вариант) не добавляется в тему; исправление серой подложки в стеке меняет
только цвет `magic_gray_4`, без замены изображений папки.
Однако одного отсутствия этих изображений недостаточно для сохранения
стеклянного фона: лаунчер может отключить размытие из-за настроек иконок.

### 1.31

Добавлены настройки совместимости HONOR, сохраняющие стеклянное размытие
маленьких папок при применении только иконок, без добавления изображения
папки. Исправлено мигание предпросмотра при изменении масштаба: до окончания
перерисовки показывается прежняя иконка, устаревшие задачи удаляются из очереди.
В окне настройки фона показаны три системные иконки и три иконки из пака;
масштабы фона и иконок, обрезка и область применения настраиваются там же.
Для уже выбранного фона это окно можно повторно открыть кнопкой **Настройки
фона**. Масштаб иконок убран из «Параметров иконок».

### 1.32

Добавлены фильтры системных иконок без замены из пака или файла:
цветокоррекция и позиция. Фильтры можно добавлять, удалять и переставлять;
предпросмотр до шести иконок закреплён над настройками. Цветокоррекция
включает яркость, контраст, насыщенность, каналы RGB, точку чёрного
и непрозрачность. Позиция меняет масштаб, смещение и плоский наклон по X/Y,
не перемещая фон, маску и накладку. Результат сохраняется в тему готовыми PNG
в разрешении экспорта; цепочка фильтров сохраняется в черновике и шаблонах.

В список добавлены приложения, установленные только в доступном рабочем
профиле, например Max в Island. Добавлен системный ярлык Parallel Space;
его иконка экспортируется под правильным ключом `com.hihonor.parallelspace`,
а назначения из промежуточной сборки с ошибочным ключом переносятся
автоматически. Для получения изменений нужно заново экспортировать тему
и применить её вручную.

### 1.33

Добавлен выбор разрешения экспорта отдельно для каждого пака:
исходный размер, 256, 192, 128 или 96 px. Объединённый набор сохраняет
размеры своих источников вместо приведения всех PNG к общему максимуму.
Размеры сохраняются в черновике и шаблоне. После экспорта показывается размер
файла и предупреждение свыше 290 МиБ о возможной невидимости темы в HONOR.
