# Icon Foundry

**Ваши иконки. Ваша тема.**

Android-приложение, которое превращает установленные иконпаки в темы `.hnt`
для штатного лаунчера HONOR MagicOS 10+. Android 15+, без root, рекламы,
сетевого доступа и разрешения на всю память.

[Сайт](https://tolivedevelop.github.io/Icon-Foundry/) ·
[Скачать APK](https://github.com/ToLiveDevelop/Icon-Foundry/releases/latest) ·
[Сообщить о проблеме](https://github.com/ToLiveDevelop/Icon-Foundry/issues)

## Возможности

- Обнаружение установленных иконпаков с `appfilter.xml`.
- Ручная замена иконок, в том числе из других установленных паков.
- Иконки из файлов с предпросмотром перед назначением. Копии изображений
  сохраняются внутри шаблона, исходные файлы после импорта не нужны.
- Экспорт только установленных приложений или всех сопоставлений пака,
  включая будущие установки.
- Маски для системных иконок: круг, скруглённый квадрат, сквиркл, квадрат
  и капля. Размер определяется по типичному видимому размеру иконок пака.
- Обложка с обрезкой 9:16 или автообложка из 12 разных иконок:
  популярные приложения и алфавитное заполнение недостающих мест.
- Необязательные пользовательские обои для рабочего стола и блокировки.
- Шаблоны с параметрами, обложкой, обоями и ручными назначениями.
  Иконки из паков хранятся как ссылки на пакет и ресурс, поэтому пересборка
  использует свежие изображения после обновления пака. Иконки из файлов
  встраиваются в шаблон как PNG.
- Экспорт в выбранный пользователем `Honor/Themes` с проверкой SHA-256.
  Имя `.hnt` создаётся из названия темы, даты и времени с миллисекундами;
  при повторном экспорте создаётся новый файл, старые не заменяются.
- Чёрный интерфейс с янтарным акцентом.

## Использование

1. Установите APK из [последнего релиза](https://github.com/ToLiveDevelop/Icon-Foundry/releases/latest).
   Android запросит разрешение на установку из выбранного источника.
2. Откройте шаблон или создайте новую тему. Выберите пак-основу
   и название. Имя файла формируется автоматически.
3. Настройте обложку, состав, форму и ручные назначения. При желании
   добавьте свои обои: одно изображение используется для рабочего стола
   и экрана блокировки.
4. В системном диалоге предоставьте доступ к существующему каталогу
   `Внутренняя память → Honor → Themes`.
5. Нажмите **Создать тему**. После записи `.hnt` автоматически сохраняется
   шаблон. Существующий шаблон обновляется; флажок **Сохранить как новый
   шаблон** создаёт отдельную запись.
6. Откройте штатные **Темы** HONOR и примените созданную тему вручную.

**Важно:** для исправления серого фона иконок в стеке папки нужно применить
тему целиком, не только иконки. При полном применении «Темы» HONOR могут
подставить запасные обои, если своих обоев в файле нет. Отсутствие обоев
в `.hnt` не гарантирует сохранение текущих. Приложение само тему или обои
не применяет и текущие системные обои не читает.

## Совместимость и ограничения

Минимальная версия Android — 15 (API 35), целевая — API 37. Формат исследован
по реальным темам и установленным приложениям HONOR; поведение других версий
лаунчера может отличаться. Проект не связан с HONOR и не заявляет официального
соответствия дизайн-гайдлайнам MagicOS.

Поддерживаются XML из ресурсов и assets, `drawable.xml`, `drawable`/`mipmap`,
растровые, векторные и адаптивные иконки. Некорректный XML пака или исчезнувшее
ручное назначение вызывают явную ошибку, а не скрытую подмену изображения.
Не все Android-иконпаки предоставляют совместимый интерфейс.

Динамический календарь фиксируется на дне загрузки пака, часы и анимации
становятся статичными. Подложки самого иконпака не воспроизводятся.
Экспортируются ярлыки текущего пользовательского профиля; рабочие и
клонированные профили отдельно не перечисляются.

В полном режиме экспортируются сопоставления `appfilter`, а не все
альтернативные изображения без привязки к приложению. Подхватывание иконок
для будущих установок зависит от лаунчера. Ручные назначения и исключения
имеют приоритет. Разные ярлыки одного приложения могут иметь отдельные иконки.

Маска не меняет PNG из пака. Её размер оценивается по медиане видимых границ
до 48 уникальных сопоставленных иконок с порогом альфа 128. У неоднородных
паков это оценка общего размера, а не гарантия одинаковой воспринимаемой
площади. Дополнительная нормализация лаунчером требует проверки после
ручного применения.

Шаблоны и черновик хранятся локально и сохраняются при обновлении с тем же
ключом подписи. Удаление приложения или очистка данных удаляют их.
Старое вручную заданное имя файла в шаблоне больше не используется; остальные
параметры, ручные назначения и вложенные изображения сохраняются.

### Обновление темы в приложении HONOR

С версии 1.9 файл получает имя вида
`Моя тема_2026-10-29_15-55-19-385.hnt`. Недопустимые файловые символы заменяются
на `_`, длинная основа сокращается; дата, время и расширение сохраняются.
Название в метаданных остаётся заданным пользователем, без даты. Новый файл
защищает предыдущий архив от перезаписи, **но не гарантирует новую или
обновлённую запись в «Темах»**. При совпадении имени экспорт завершается ошибкой,
а не заменяет существующий файл. Старые `.hnt` автоматически не удаляются.

Замена `.hnt` не гарантирует обновления его записи в «Темах»: приложение HONOR
ведёт собственную базу установленных тем и распакованный кэш. В исследованной
версии совпадение названия и дизайнера считается той же темой; переименование
одного файла поэтому недостаточно. Очистка кэша не обязательно удаляет запись
из базы. Публичный поддерживаемый интерфейс принудительного пересканирования
для сторонних приложений не найден.

Если после замены видна старая тема, используйте подтверждённый пользователем
порядок: **сначала удалите старую запись в «Темах», затем заново создайте тему
в Icon Foundry**, после чего выберите её и примените вручную. Удаление записи
может удалить и исходный `.hnt`, поэтому создавать замену нужно после удаления,
а не перед ним. Другой вариант — отдельная тема с другим названием и именем
файла; это не обновление существующей записи.

Автоматическое повышение внутренней версии темы намеренно не включено:
в исследованном коде HONOR путь обновления удаляет архив предыдущей версии,
и безопасность замены по тому же пути не подтверждена. Проверка отдельной
временной темы не подтвердила надёжное обнаружение нового файла через интерфейс.
Icon Foundry не удаляет записи в «Темах», не очищает их данные и не применяет
тему автоматически.

Коммерческие иконки предназначены для личного использования. Приложение
не содержит изображения из сторонних паков или официальных тем. Не
распространяйте созданные темы без разрешения правообладателей.

## Сборка

Нужны JDK 25, Android SDK Platform 37 и настроенный `ANDROID_HOME` либо
локальный `local.properties` с `sdk.dir`. Gradle Wrapper включён в репозиторий.

```powershell
.\gradlew.bat --no-daemon :app:assembleDebug :app:lintDebug
```

APK: `app\build\outputs\apk\debug\app-debug.apk`.

Текущие публикуемые APK — debug-сборки, подписанные одним локальным
отладочным ключом. Самостоятельная сборка на другой машине получит другой
ключ и не установится поверх опубликованной без удаления приложения.
Ключи подписи в репозиторий не включаются.

### Проверки на устройстве

```powershell
.\tools\device-test.ps1
```

Нужны авторизованный ADB, установленный Premium Icons, образец темы
`/sdcard/Dev/Luminescence.hnt` (путь меняется параметром `PhoneReference`),
паки для межпаковых и геометрических проверок и ранее предоставленный
приложению доступ к `Honor/Themes`. Runner использует специфичные для
исследованного HONOR проверки, включая Contacts/Dialer. Это интеграционный
набор для подготовленного устройства, а не универсальный эмуляторный тест.

Скрипт собирает APK, запускает lint, устанавливает приложение и тестовый APK,
проверяет экспорт через SAF и удаляет собственные временные темы, не применяя
их. Тестовый пакет после проверки можно удалить:
`adb uninstall dev.iconmanager.test`. Пользовательские темы не заменяются.

## Формат экспорта

Внешний ZIP `.hnt`: `description.xml` с корнем `HnTheme`, вложенный ZIP `icons`,
каталог `preview/`, обложки `cover.jpg` и `preview_icons_0.jpg` 720×1280,
миниатюра `icon_small.jpg` 180×320.

В `author` и `designer` указывается `Icon Foundry by ToLive`. Описание:
«На основе иконпака „название пака“. Права на иконки принадлежат разработчику
иконпака. Только для персонального использования». Имя разработчика пака
не угадывается: стандартного Android-поля для него нет.

В `icons` — плоские `<package-or-activity>.png` 192×192 и необязательная
`icon_mask.png`. Для исправления стека добавляется ZIP-модуль
`com.hihonor.android.launcher` с `theme.xml` и `night/theme.xml`, задающими
только прозрачный цвет `magic_gray_4`. Он также влияет на фон стандартного
неизвестного ярлыка в ночном режиме.

Явно выбранные обои добавляются как `wallpaper/home_wallpaper_0.jpg` и
`wallpaper/unlock_wallpaper_0.jpg`. JPEG ограничен длинной стороной 3200 px,
пропорции сохраняются. Обрезку под экран выполняют «Темы». Модули блокировки,
AOD, шрифты и настройки сторонних тем не копируются.

## Публикация версий

Для каждой законченной версии повышаются `versionCode` / `versionName`,
изменения проверяются, коммитятся и отправляются в этот репозиторий.
Тег `v<versionName>` соответствует GitHub Release с локально собранным
`Icon-Foundry.apk`. Сохраняйте ключ подписи для совместимых обновлений.

Посадочная страница находится в `docs/`. Workflow
`.github/workflows/pages.yml` публикует её в GitHub Pages при изменениях
в `main`. Настройки Pages должны использовать **GitHub Actions**.

Файловые назначения работают в обоих режимах экспорта; исходное изображение

обновления записей в «Темах» HONOR; рискованная автоматическая смена версии
метаданных не включена.

### 1.9

Убран дублирующий нижний лоадер: над кнопкой остаётся только центрированная
подпись об автосохранении черновика, загрузка показывается в popup или скелетоне
выбора пака. Пояснения сокращены с сохранением ограничений. Имя файла больше
не запрашивается и не хранится в параметрах шаблона: каждый экспорт получает
название с датой и временем. Название самой темы не меняется. Обновлены авторство
и описание темы с указанием базового иконпака и персонального использования.
